# tls-net v0.9.0 - Beta

**Beta, API frozen.** v0.9.0 is the result of an adversarial review of the whole crate: three reviewers, each over one area, with no access to the author's notes. They found two high, two medium, and nine low findings. Every one is fixed, and each fix has a test that fails on 0.8.0. From here the API changes only by addition (the exporters, when rustls 0.24 is released) or to fix a finding.

## Security

- **A split post-handshake message could crash a session** (D-126, T-29). A peer that sent one valid record holding part of a ticket or key update made `encrypt` and `close` panic, in release builds too: rustls kept the part in the caller's input and was then called on an empty buffer. net-io calls `close` on every graceful close, so any peer could reach it. Both now return `WrongState` until `step` has the rest of the message.
- **Resumption skipped client authentication** (D-125, T-30). rustls does not ask for a certificate on resumption. After a publish that required client certificates, dropped a pin, or added a CRL, old sessions still resumed, and a client that resumed every ticket period kept its identity past its certificate's expiry. Tickets and cached sessions are now bound to each host group's client-auth rules, and a resumed handshake is refused when a required certificate is missing or the certificate has expired.
- **The lenient hello path skipped the hook** (D-127). With `refuse_malformed(false)`, a peer that went over a budget skipped the hello hook, host groups, and a required ALPN. That path is now taken only where none of those exist, and a required ALPN is checked again at completion, which also covers a second hello after a HelloRetryRequest.
- **A ticket-key hand-off could freeze rotation** (D-130). An export from a ring with another period, or from a clock running ahead, set an epoch the importer reached only much later. Exports now carry the period, and an epoch more than one ahead is refused.

The low findings are listed in `docs/SECURITY.md`, among them: `close` losing close_notify into a short buffer, `Policy::internal()` admitting anonymous clients, `publish` ignoring a new handshake limit, pinned client identities never resuming, and OCSP staples sent with the wrong certificate.

## Upgrading from 0.8

- `Ja4::from_str` is now `Ja4::parse`.
- `Policy::internal()` needs `ClientAuth::required` or `pinned` at `build`, and CRLs need anchors.
- Tickets and ticket-key exports from 0.8 do not open in 0.9 (their authenticated data changed), so the upgrade costs each client one full handshake.
- A publish that changes a group's client-auth rules now ends resumption for that group: one full handshake per client.

## Added

- `ClientHelloView::server_name_raw`: the SNI bytes as sent, for forensics.

## Costs

The resumption binding adds 32 bytes of associated data per ticket (an estimate: under 50 ns), and a read of the client certificate per resumed handshake that carries one (an estimate: 1 to 2 µs). The split-message check is one record-header test per `step`. Nothing else changed on the per-record path.
