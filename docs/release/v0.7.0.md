# tls-net v0.7.0 - Hardening

**Hardened.** v0.7.0 checks every threat in the model against an attack test, fuzzes every parser and both session sides for 24 hours from real ClientHellos and server flights, runs a 6-hour soak with reloads and ticket rotation, and runs testssl.sh and tlsfuzzer against the example server every week. The API is unchanged. The full record is in `docs/SECURITY.md`.

## Fixed

- **A ClientHello in a `0x0300` record was refused** (D-110, found by tlsfuzzer). The parser accepted record versions `0x0301` to `0x0303` only, so a hello from an older stack, or from tlsfuzzer, was refused with no alert before rustls saw it. RFC 5246 appendix E.1 requires a server to accept any `{03,XX}`, and rustls does. The record version never selects the protocol, so this had no security effect.
- **A second fatal alert after a failure** (D-111, found by the session fuzz targets). After a rustls error, tls-net called rustls again to collect the alert; when nothing was queued, rustls read the next record, and a second malformed record made it queue a second fatal alert. That trips a `debug_assert!` in rustls: in a debug build of an application, bytes from a peer caused a panic. Release builds only queued an alert that was never sent. A failed session now hands out only what rustls had already queued. Both sides have regression tests that replay the fuzzers' inputs.

Both are in 0.3.0 to 0.6.0. Upgrading is recommended for anyone who runs debug builds where peers can reach them.

## Hardening record

- **Threats.** T-1 to T-28 each have an attack test. The audit found 20 whose test was missing a part of what the plan describes, and closed each: the TLS 1.3 downgrade sentinel, groups rewritten in transit, expired, self-signed, and revoked certificates, a stalled handshake giving its slot back at net-io's deadline, 50-certificate and 1 MiB client chains, and an opt-in timing test for probing hosted names, among others.
- **Fuzzing.** Six targets, 24 hours each with AddressSanitizer and debug assertions, seeded with 18 ClientHellos from Chromium, Windows Schannel, OpenSSL, curl, wget, Python, and rustls, and 7 server flights. One finding (D-111), fixed. Long runs now detect hangs by progress instead of libFuzzer's wall-clock timeout (D-115).
- **Soak.** 6 hours on net-io's reactor: 21.4 million handshakes, half resumed, a certificate reload every minute and a ticket epoch every 10 minutes, with no handshake failed by the server. A new test checks the same work against live heap bytes: no growth.
- **Conformance.** testssl.sh reports no vulnerability. Ten tlsfuzzer scripts pass in full and fail the job if they regress; every other script is classified by the reason it cannot pass: tls-net's deliberate no-alert refusal of hellos it cannot read or that exceed a budget, rustls's choice of alert, or features rustls does not have.
- **Miri** runs in CI on the parsers, the ticket code, and the rest of the library that needs no crypto provider.

## Measured on net-io 0.6.2

net-io 0.6.2 spreads short connections across workers on one shared listener; that setup now matches one listener per worker. All 9,000 idle connections open, where 0.6.1 stopped at 4,096. Numbers are in `docs/PERFORMANCE.md`.

## What's next

- `0.7.1`: support for net-io 0.7, which gives an idle connection's TLS buffers back to the pool, and the idle memory measured on it.
- `0.8.0`: the alpha. The consumers' shapes run in this repository against real binaries: a net-io server in direct mode, a back-channel pair with mutual TLS, and a STARTTLS client against a local mail server, with interop against curl, OpenSSL, and Go in CI.
