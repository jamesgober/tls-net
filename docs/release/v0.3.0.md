# tls-net v0.3.0 - Core

**TLS works.** v0.3.0 serves and connects over TLS 1.3 and TLS 1.2 through rustls's sans-IO API, checks every certificate before using it, selects certificates by SNI, refuses anything weak by construction, and plugs straight into net-io as its TLS engine.

## What's in 0.3.0

- **One-call setup.** `server_from_files(chain, key)` and `client()` cover the common cases; `ServerBuilder` and `ClientBuilder` add several certificates, ALPN, a policy, and budgets.
- **Sessions that never touch a socket.** `step` takes ciphertext from a buffer the caller owns and writes records into another; plaintext comes back as a slice of the input. A driver runs the same loop on a blocking thread, a reactor, or a completion port.
- **net-io adapter.** With the `net-io` feature (on by default) a `TlsServer` is a net-io `TlsAcceptor`, so serve-net and other net-io servers get TLS by passing it to `ServerBuilder::tls`. Works with net-io 0.4 to 0.6.
- **Policies that cannot be weak.** TLS 1.2 and 1.3 only, AEAD suites with ECDHE only, extended master secret required for TLS 1.2, X25519MLKEM768 post-quantum key exchange offered first. Presets `compatible`, `modern`, and `internal` (TLS 1.3 and post-quantum only).
- **Certificates checked at load time.** Size limits before reading, key file permissions on Unix, encrypted keys named, key match, validity, SAN name coverage, key size, SHA-1 refusal, extended key usage, and chain order, each with its own error code.
- **SNI.** Exact and wildcard names, an ECDSA and an RSA certificate for one name, a default certificate or a refusal that sends the same 7 bytes for every unknown name.
- **ClientHello parser.** Bounded and zero-copy across records, ready for the JA4 fingerprints of 0.4.
- **STARTTLS.** `start_after_plaintext` refuses a session when any byte arrived after the upgrade reply.

## Measured and checked

- tls-net's own code allocates nothing on the established record path: a counting-allocator test sees exactly rustls's one allocation per record in each direction.
- Interop: OpenSSL 3.5 `s_client` over TLS 1.3 with X25519MLKEM768, X25519, P-256, and P-384, OpenSSL 3.0 and curl over TLS 1.3 and 1.2; the tls-net client verifies public sites with the Mozilla roots.
- Fuzz targets for the hello parser, the DER reader, PEM intake, and server and client sessions ran without findings.

## Known limits

- rustls 0.23's unbuffered API copies each received record into its own buffer, so tls-net copies the plaintext back into the caller's input (D-035, D-063). The cost is measured in 0.6; rustls 0.24 may remove it.
- Exporters and channel binding wait for rustls 0.24 (D-052).

## What's next

`0.4.0`: mutual TLS and pinned identities, hot reload, session tickets under a rotating key ring, JA4 and JA3 fingerprints with a hook for the connection gate, key-vault custody, expiry reports, and OCSP staples.
