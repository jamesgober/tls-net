# tls-net v0.9.1 - Polish

**Polish, no API change.** Three things: refusal alerts are now reported as documented, the hand-off import has its fuzz target, and the 1.0 readiness note lists every gate item with its status.

## Fixed

- **Refusal alerts were missing from events** (D-139). `ServerSession::alert`, `ClientSession::alert`, and `TlsEvent::HandshakeFailed` were documented to report the alert sent or received. They only reported received alerts and tls-net's own two (`unrecognized_name`, `no_application_protocol`). Two cases are now reported:
  - A refused certificate, with the alert rustls sends for it. A client key that matches no pin gets `certificate_unknown` (46), an untrusted chain gets `unknown_ca`, and so on.
  - A missing client certificate that the server requires (`certificate_required`, 116).

  rustls picks every other alert internally and does not expose its choice, so those are still `None`, as the docs now say. The cost is one match on the failure path and none on success.

## Tests

- **`import_sealed` fuzz target** (D-140). The testing plan named it, but it had not been built. It checks two things:
  - Arbitrary bytes given as a ticket-key hand-off never import.
  - The same bytes, sealed as an export's plaintext under the right key and header, import exactly when they have one of the two layouts an export writes.

  A short first run is clean; the 24-hour run is a 0.9.x item.
- **Diagnostics in the back-channel tests.** These tests now print:
  - the server's events,
  - the socket error behind `UncleanClose`,
  - the peer's alert, when it arrived before a reset.

  This is so the one unexplained CI failure from 0.9.0 can be traced if it happens again. A TLS 1.3 client finishes its handshake before the server checks its certificate, so any refusal on the server reaches the client as a reset on its first write. That makes a refused valid peer the likely cause, rather than the transport (ROADMAP 0.9.x).

## Documentation

- **`docs/STABILITY-1.0.md`**: the 1.0 readiness note. Three gate items are open, and none of them is in tls-net's code:
  - CPU per handshake end to end, which waits on net-io 0.8 (D-106);
  - production use by the first site's direct mode and by smtp-net;
  - the 24-hour soak.

  The note also lists the decisions left for 1.0.

## Upgrading from 0.9.0

Nothing to change. Code that matched `alert: None` for a refused certificate now gets the alert's code.
