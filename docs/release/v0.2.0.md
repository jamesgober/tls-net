# tls-net v0.2.0 - Design Lock

**The API is written down.** v0.2.0 locks the public API that `0.3.0` to `1.0.0` build, answers every open design question, and wires every planned feature to its dependency so CI proves the whole tree builds on Linux, macOS, and Windows at Rust 1.85. No TLS code ships in this release. It is the first tls-net release on crates.io.

## What is tls-net?

tls-net gives net-io TLS without net-io depending on a TLS library. It is a thin adapter: rustls does the cryptography and the protocol, and tls-net drives rustls's sans-IO connection API, loads and checks certificates, selects them by SNI, reloads them without dropping a connection, applies a policy that cannot express anything weak, and parses the ClientHello for fingerprints.

## What's in 0.2.0

- `docs/API.md` with every public item, its tier, grade, version, errors, and cost, and examples for a public HTTPS server, SNI with several certificates, reload on a signal, a mutual-TLS back-channel, SMTP STARTTLS, an outbound client, and a fingerprint hook.
- `dev/PLAN.md` with requirements, the design, threats T-1 to T-28, performance targets, and decisions D-004 to D-051.
- Cargo features `aws-lc` (default), `ring`, `prebuilt-nasm`, `webpki-roots` (default), `platform-verifier`, `key-vault` (default), `net-io`, `ja3-md5`, `rustls-escape-hatch`, `dangerous-keylog`.
- `deny.toml` bans other TLS stacks, async runtimes, and the archived rustls-pemfile.

## Decisions worth knowing

- The crypto provider is aws-lc-rs by default, because ring has no post-quantum key exchange group (D-004).
- Clients trust the bundled Mozilla roots by default, the same on every platform (D-005).
- rustls 0.23's unbuffered API copies each received record into its own buffer before handing it out, so tls-net copies the plaintext back into the caller's buffer to keep the zero-copy seam shape. The cost is measured at 0.6 and revisited with rustls 0.24 (D-035).
- The ClientHello parser, the net-io adapter, and the STARTTLS helper move up to 0.3, so serve-net and smtp-net can use real TLS from the first functional release (D-036 to D-038).
