# tls-net v0.7.1 - net-io 0.7

**net-io 0.7 support.** tls-net now accepts net-io `>= 0.4, < 0.8`, so servers on net-io 0.7 can use it. There is no code change and no API change: net-io 0.7.0's seam changes are additions, and every test passes against it, including the adapter's end-to-end tests over net-io's reactor.

## Changed

- The `net-io` dependency range is `>= 0.4, < 0.8` (was `< 0.7`, D-121). CI still builds against net-io 0.4.0, the lowest release in the range.

## Measured on net-io 0.7.0

| Idle connection | tls-net on net-io 0.7.0 | tokio + tokio-rustls |
|---|---|---|
| after the handshake | 8,971 bytes | 11,447 bytes |
| after a 32 KiB page | 42,030 bytes | 11,651 bytes |

A connection that has not carried data costs 22% less than one on tokio-rustls. One that has carried a page still holds net-io's spare buffers: net-io 0.7.0 releases them while a connection is idle, but its reactor skipped that for a TLS session waiting for input (net-io D-200). The fix is in net-io 0.7.1, which this release accepts; the figure will be re-measured on it in `docs/PERFORMANCE.md`.

## What's next

- `0.8.0`: the alpha. The consumers' shapes run in this repository against real binaries (a net-io server in direct mode, a back-channel pair with mutual TLS, STARTTLS against Postfix) with interop against curl, OpenSSL, and Go in CI, and a mutual-TLS peer's key hash reaches net-io's `TlsInfo`.
