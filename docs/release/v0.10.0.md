# tls-net v0.10.0 - Simplicity

**A simpler API, a few renames, and security fixes.** I went through the API against how serve-net, smtp-net, and tls-net's own tests actually use it, and fixed what was harder than it needed to be. This release also fixes a host policy bypass and several smaller bugs, each with a regression test. Most code needs no change. Every rename, removal, and changed behaviour is in `docs/MIGRATION-0.10.md`. **A server with host policies must add the `Host` check below.**

## Security

- **Host policies need a `Host` check.** A `HostPolicy` applies its rules by the SNI the client sends. A client could send no SNI, or another name the same certificate covers, get the default group's rules (for example no client certificate), and then ask for the protected host. The HTTP layer now has a one-line check:

  ```rust,ignore
  let scope = server.host_scope(info.server_name); // once per connection; or net-io's sni()
  if !scope.permits(host) { /* 421 Misdirected Request */ }
  ```

  `HandshakeInfo::peer_verified` says whether the peer's certificate was verified.
- **Expiry thresholds.** A certificate living under 2 days was `Critical` from the moment it was issued. A certificate is now `Ok` at issue, however short its life.
- **Client CRLs.** A client's CRLs need trust anchors, and a client with CRLs needs `require_chain` on a pinned identity. Before, the CRLs could be accepted and never applied.
- **Reload.** An established session no longer keeps the old configuration, private keys included, alive after a reload.
- **Limits.** `LoadLimits` and `HandshakeLimits` fields set directly are clamped to their ranges.
- **Builder order.** Builder settings work in any order, so startup and reload check the same files the same way.
- **Tickets** open for their advertised lifetime of one period, not up to two. Tickets from 0.9 are refused once after the upgrade.
- **net-io.** An ALPN name over 32 bytes is refused at `build`; net-io would have reported it as no ALPN.
- `Policy::versions` on a preset now brings the preset's suites along, and four documentation errors are fixed.

## Added

- **`TlsStream`.** A client or server now runs over a `TcpStream`, or any other blocking `Read + Write`, in one call:

  ```rust,ignore
  let mut tls = tls_net::client()?.connect_stream("example.com", tcp)?;
  let mut conn = server.accept_stream(tcp)?;
  ```

  Before this, using a session over a socket meant writing a loop around `step` by hand. Three copies of that loop existed, the longest about 300 lines. For a session made another way (STARTTLS, a pinned identity), `TlsStream::client` and `TlsStream::server` take the session.

  `read` returns `Ok(0)` only after the peer's `close_notify`. A connection that ends without it is an `UnexpectedEof` error carrying `UncleanClose`, so the easy path cannot mistake a truncated response for a complete one.
- **`TlsError::Transport { kind }`** (`TLS-0047`): the transport under a `TlsStream` failed.
- **`HostScope`** and `TlsServer::host_scope`, for the `Host` check.

## Changed and removed

| 0.9 | 0.10 |
|---|---|
| `ClientBuilder::new()`, `ServerBuilder::new()` (and `Default`) | `TlsClient::builder()`, `TlsServer::builder()` |
| `server.handshakes_in_progress()`, `server.sni_disagreements()`, `server.version()` | `server.stats().in_progress`, `.sni_disagreements`, `.config_version` |
| `ServerStats::snapshot_version` | `ServerStats::config_version` |
| `ServerReader`, `server.reader()` | `WorkerAcceptor`, `server.worker_acceptor()` |
| `HelloParser::parse(input, &limits)` | `parse_client_hello(input, &limits)` |
| `INCOMING_MIN`, `OUTGOING_MIN` | `MIN_INPUT_BUFFER`, `MIN_OUTPUT_BUFFER` (same values) |
| `HandshakeLimits::max_in_progress(n)?` | `HandshakeLimits::max_in_progress(n)` (it could not fail) |

Each change leaves one way to do a thing, with a name that says what it does.

## Documentation

`docs/API.md` now follows the house format. Every example in it and in the README is compiled as a doctest, so the documentation can no longer drift from the API; most examples also run. Before this release, none of its 85 code blocks was compiled.

## Costs

Nothing changes on an existing path: the removed methods' values come from `stats()`, which reads the same atomics. A `TlsStream` holds an input buffer of `MIN_INPUT_BUFFER` (grown for a larger hello or chain) and an output buffer of `MIN_OUTPUT_BUFFER`. It copies a record's plaintext once when the caller's read buffer is smaller than the record.

The fixes cost nothing measurable, and one saves time. Against rustls alone (median of 4 alternating rounds against the first 0.10.0 build), a full handshake went from 1.9% over rustls to 1.1%, a resumed one from 3.5% to 1.6%, and the client side from 1.4% to 0.6%, because the peer identity is no longer built when nobody reads it. The record paths did not move. `host_scope` is one lock and an `Arc` clone per connection (estimated 60 ns), and `permits` two hash lookups per request (estimated under 100 ns). A ticket is 8 bytes longer.

## Upgrading from 0.9

- serve-net's TLS test uses `ClientBuilder::new()`; it becomes `TlsClient::builder()`. serve-net and web-net should check each request's `Host` with `HostScope::permits` and answer `421` when it is `false`.
- smtp-net uses none of the changed items. Its TLS layer can use `tls_net::MIN_INPUT_BUFFER` where it hard-codes `18_437`.
