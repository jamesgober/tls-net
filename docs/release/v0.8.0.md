# tls-net v0.8.0 - Alpha

**Alpha.** v0.8.0 runs the shapes tls-net's consumers use, end to end in this repository and in CI: a net-io server terminating TLS in direct mode, a back-channel between two services with mutual TLS and pinned keys, and an SMTP client upgrading with STARTTLS against Postfix. Go's crypto/tls joins OpenSSL and curl as an interop peer, both ways. The API is unchanged.

## Changed

- **net-io 0.7 or later is required** (`>= 0.7, < 0.8`, D-122). Applications on net-io 0.4 to 0.6 stay on tls-net 0.7.
- **The verified client key reaches net-io.** The seam sets `TlsInfo::peer_spki_sha256` to the SHA-256 of the client certificate's public key, so an application on net-io can map a mutual-TLS peer to a principal. Before, a server admitted only pinned peers but could not tell which one connected (finding D-120). The hash is set only for a certificate rustls verified, by its chain or a pin. Cost: a 32-byte copy once per handshake, no allocation.

## Added

- **Consumer shapes** (`tests/consumers.rs`, D-119), using public API only, the way each consumer does:
  - Direct mode: a net-io server on the `Auto` driver serving two sites by SNI with ALPN and tickets, reloaded 20 times while four clients connect, and checked with curl, OpenSSL, and Go.
  - Back-channel: tls-net on both ends over net-io, the server pinning client keys and the client pinning the server's. Other keys and anonymous clients are refused, and two pinned peers on one server each arrive with their own key hash.
  - STARTTLS: EHLO, STARTTLS, upgrade, EHLO, and QUIT, against a scripted server everywhere and against Postfix in CI.
- **Go interop** (`tests/go.rs`, D-118): a Go client against tls-net over TLS 1.3 and 1.2, with ALPN, resumption, a client certificate, and `modern` refusing 1.2; tls-net against a Go server with the same, plus a required client certificate. The Go side uses the standard library only.
- **`docs/OPERATIONS.md`**: deploying and reloading certificates, expiry states, ticket modes and the hand-off across restarts, choosing a policy, deciding from the server's counters when TLS 1.2 can go, and what each signal means.

## Measured on net-io 0.7.1

| Idle connection | tls-net on net-io 0.7.1 | tokio + tokio-rustls |
|---|---|---|
| after the handshake | 5,738 bytes | 11,418 to 11,447 bytes |
| after a 32 KiB page | 5,884 bytes | 11,680 bytes |

net-io 0.7.1 gives an idle TLS connection's buffers back to its pool, so a connection that has carried traffic now costs half what one on tokio-rustls does (it was 42,030 bytes on net-io 0.7.0). That meets the idle-memory target, which leaves the 1.0 gate (D-123). Numbers and method are in `docs/PERFORMANCE.md`.
