# tls-net v0.5.0 - Feature complete

**Every feature planned before 1.0 is in.** v0.5.0 adds an observer with events and lock-free server counters, a FIPS 140-3 build, the operating system's verifier for clients, a sealed hand-off of ticket keys from one process to the next so resumption survives a restart, and the remaining debugging and fingerprint options. From here to 1.0 the work is measurement, tuning, and hardening.

## What's in 0.5.0

- **Events.** A `TlsObserver` on a server or client receives handshake completions and failures, ClientHello refusals (with the reason), sampled ClientHellos, reloads, expiring certificates, ticket key rotations, and capacity limits. Events allocate nothing, and every string in them is the normalised SNI or a configured ALPN name, so they are safe to log as they are. The capacity event is limited to one per second so a flood does not turn into observer calls.
- **Counters.** `TlsServer::stats()` reads full, resumed, and failed handshakes, refusals, tickets issued and rejected, TLS 1.2 handshakes, post-quantum handshakes, and SNI disagreements, without a lock. The TLS 1.2 and post-quantum counts tell you when TLS 1.2 can go and how many clients already use X25519MLKEM768.
- **FIPS.** Feature `fips` builds aws-lc-rs's FIPS 140-3 module; `Policy::fips()` limits suites and groups to the approved ones and `is_fips()` reports rustls's own check. `Policy::fips()` compiles in every build and is refused at build time outside a FIPS build.
- **Platform verifier.** `TrustAnchors::platform()` verifies with the operating system's store, for clients inside networks that add their own roots.
- **Restarts without losing resumption.** `ticket_keys().export_sealed(wrap_key)` in the old process and `import_sealed` in the new one move the ticket keys, sealed with XChaCha20-Poly1305; a wrong key, any tampering, or an old export is refused. `rotate_now` throws the keys away at once if you suspect a leak.
- **Also.** `Policy::summary()` for audit logs, the JA3 MD5 label, read-only access to the rustls configurations, and an NSS key log for debugging (refused with FIPS).

## Checked

- The hand-off test runs two real processes and resumes a session across them.
- Attack tests for key bytes in any `Debug` or `Display` output, banned crates in the tree, wrong or tampered sealed keys, half-open handshakes, and an opt-in timing test of the pin comparison.
- STARTTLS against a scripted relay and a public mail relay; the platform verifier against public sites on Linux, macOS, and Windows; a FIPS build and test run on Linux.

## Build notes

`fips` needs CMake and Go (and NASM, Ninja, and clang on Windows). Per-platform build needs, the key file permission check, and how the trust anchor choices differ are in `docs/PLATFORM-NOTES.md`.
