# tls-net v0.4.0 - Extended

**Everything a production listener needs beyond the handshake.** v0.4.0 adds mutual TLS with pinned identities, per-host policies, hot reload without dropping a handshake, session tickets under a rotating key ring, JA4 fingerprints with a hook for the connection gate, private keys held in key-vault, expiry reports, and OCSP staples.

## What's in 0.4.0

- **Mutual TLS.** `ClientAuth::required`, `optional`, or `pinned`, with CRLs and hidden CA names; `ClientBuilder::client_certificate` for the dialing side; the peer's certificate identity (`PeerIdentity`: SPKI SHA-256, SANs including URI names, serial, validity) on both sides.
- **Pins that still verify.** A pinned server or client key is checked on top of the handshake signature, so a copied public certificate gets nobody in (tested with a server that presents the pinned certificate and signs with another key). `spki_sha256` computes a pin from a certificate.
- **Host policies.** `ServerBuilder::host(names, HostPolicy)` gives names their own ALPN, required ALPN, client certificates, and policy, chosen from the SNI before the handshake starts.
- **Hot reload.** `reload_from_files` for one certificate, `ReloadHandle::publish` for a whole new configuration; everything is checked before the swap, handshakes in progress keep what they started with, ticket keys and the session cache carry over. A per-worker `ServerReader` reads the configuration with one atomic load.
- **Session tickets.** XChaCha20-Poly1305 under a key ring: `Ephemeral` (default), `Ratchet` (old keys cannot be recomputed), or `Derived` (shared across a cluster). Rotation is lazy; there is no timer.
- **Fingerprints and the hook.** JA4 (matching FoxIO's published example), JA4_r, JA4_o, and the JA3 string; a `HelloHook` sees the parsed ClientHello and its fingerprint before the handshake and can refuse it without an alert.
- **Key custody.** `KeySource::Vault` keeps private keys in key-vault, parsed once (`Resident`) or for every signature (`PerSignature`).
- **Operations.** `expiry_report` with proportional thresholds; OCSP staples checked when given.

## Checked

- Attack tests for forged pins, post-quantum stripping on internal listeners, missing ALPN on a strict host, ticket tampering and old epochs, half-written reload files, oversized client chains, and a resuming client that wants 0-RTT (it gets no window).
- loom model checks of the configuration snapshot, the capacity gate, and the ticket ring; a reload-under-load test with no failed handshake; a new fuzz target for tickets.

## Changed

- `KeySource` is `Clone` instead of `Copy`.
- `HelloLimits::max_ciphers` accepts 1 to 1,024.

## What's next

`0.5.0`: observer events and server statistics, the FIPS build, the platform verifier, sealed ticket key hand-off across restarts, the JA3 MD5 label, and the rustls escape hatch.
