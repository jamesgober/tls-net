# tlsfuzzer scripts run against the example server (default policy: TLS
# 1.3 and 1.2, AEAD suites only, extended master secret required, no
# renegotiation, no compression, no 0-RTT), D-109 and D-113.
# <expect> <server> <script> [args]: `pass` must pass, so a regression fails
# the job; `report` runs and is logged, with the reason it cannot pass.
# <server> is `ecdsa` or `rsa` (the example server with that certificate).
#
# Reasons a script cannot pass, by category (counts in docs/SECURITY.md):
#   strict: tls-net refuses a ClientHello it cannot read whole, or one over
#     a budget (16 KiB, 64 extensions, list budgets), before rustls and with
#     no alert (D-014); tlsfuzzer expects decode_error or illegal_parameter.
#   rustls: rustls answers with another alert than the one tlsfuzzer
#     expects (for example decrypt_error for decode_error), or follows
#     another rule (tickets only to clients that offer psk_dhe_ke).
#   absent: the feature does not exist in rustls (TLS 1.1 and below, static
#     RSA key exchange, CBC, FFDHE, x448, brainpool curves, psk_ke,
#     renegotiation, heartbeat, compression, SSL 2 and 3).
#   rsa: the script assumes an RSA certificate (run on the rsa server too).
